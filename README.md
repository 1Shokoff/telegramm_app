# iApki — Telegram-бот + Mini App

Приём заказов на доступ к каталогу приложений для iPhone: витрина, оплата,
приём UDID, переписка с покупателем и ведение заказа продавцом. Один контейнер
с ботом и веб-приложением плюс Caddy с автоматическим HTTPS.

Воронка: **Оплата → UDID → Установка сертификата → Инструкция**.
Покупатель проходит её в Mini App или прямо в чате; продавец ведёт заказы
кнопками под уведомлениями и во вкладке «Продавец».

## Что внутри

```
app/           бот (aiogram 3) и HTTP-API (aiohttp)
  config.py    все настройки из переменных окружения
  db.py        SQLite: пользователи, заказы, история событий
  service.py   бизнес-правила: один слой для чата и Mini App
  api.py       JSON-API для Mini App + отдача статики
  handlers/    buyer.py, seller.py, payments.py (Telegram Stars)
webapp/        Mini App: index.html, styles.css, app.js, icons/
tests/         smoke_test.py (API + правила), bot_test.py (хэндлеры)
tools/         preview.py — локальный предпросмотр UI без Telegram
```

## Запуск на VPS

1. **Бот.** У @BotFather: `/newbot` → токен. Там же `/mybots → Bot Settings →
   Menu Button` можно не трогать: бот сам выставит кнопку меню на Mini App.
2. **Домен.** A-запись на IP сервера, порты 80 и 443 свободны.
3. **Свой Telegram ID** — например через @userinfobot.
4. Скопируйте проект на сервер и заполните `.env`:

```bash
cp .env.example .env
nano .env   # BOT_TOKEN, SELLER_IDS, DOMAIN, WEBAPP_URL, PAYMENT_DETAILS
```

`WEBAPP_URL` должен быть ровно `https://<DOMAIN>` — по нему Telegram откроет Mini App.

5. Запуск:

```bash
docker compose up -d --build
```

6. Проверка:

```bash
docker compose logs -f bot
curl -I https://<ваш домен>/
```

В логах должно быть `Бот @имя запущен` и `HTTP слушает 0.0.0.0:8080`.

### Обновление

```bash
git pull && docker compose up -d --build
```

Правки в `webapp/` подхватываются без пересборки — папка примонтирована в контейнер,
достаточно обновить страницу.

### Бэкап

Вся база — один файл в томе `bot_data`. Достать копию на хост:

```bash
docker compose cp bot:/data/bot.sqlite3 ./backup-$(date +%F).sqlite3
```

База лежит в именованном томе Docker, а не в папке проекта: том наследует
права от образа, поэтому непривилегированный пользователь контейнера может в
него писать. Папка с хоста создаётся от root, и бот такую базу не откроет.

`docker compose down` том сохраняет, `docker compose down -v` — удаляет вместе
со всеми заказами.

## Настройки (.env)

| Переменная | Зачем |
|---|---|
| `BOT_TOKEN` | токен от @BotFather |
| `SELLER_IDS` | ваши Telegram ID через запятую — кому падают заказы |
| `DOMAIN` / `WEBAPP_URL` | домен для Caddy и адрес Mini App |
| `PRICE_RUB` | цена в витрине |
| `PAYMENT_MODE` | `manual` (перевод + подтверждение), `demo`, `stars` |
| `PAYMENT_DETAILS` | реквизиты, которые видит покупатель; `\n` — перенос строки |
| `INSTRUCTION_TEMPLATE` | шаблон инструкции: отправляется одной кнопкой |
| `SUPPORT_USERNAME` | юзернейм для кнопки «Помощь» |
| `LEGAL_NAME` | реквизиты продавца: «Самозанятый Фамилия И. О.» или «ИП …» |
| `LEGAL_INN` | ИНН продавца |
| `LEGAL_ADDRESS` | город или адрес — необязательно |
| `CONTACT_EMAIL`, `CONTACT_PHONE` | контакты для покупателя и модерации |
| `OFFER_URL`, `REFUND_URL`, `PRIVACY_URL`, `CONSENT_URL` | внешние ссылки на документы; по умолчанию открываются свои страницы `/docs/…` |
| `BOT_USERNAME` | запасной юзернейм бота для кнопки «Оформить в Telegram»; обычно определяется сам |
| `ORDER_PREFIX` | префикс номеров заказов (`NP-0001`) |
| `DEV_MODE` | вход в API без подписи Telegram — **только локально** |

### Режимы оплаты

- **manual** (по умолчанию) — покупатель платит переводом по реквизитам из
  `PAYMENT_DETAILS`, жмёт «Я оплатил», вам приходит уведомление с кнопками
  «Оплата получена» / «Отклонить». Деньги бот не трогает.
- **demo** — оплата имитируется, ничего не списывается. Для проверки воронки.
- **stars** — инвойс в Telegram Stars (`PRICE_STARS` в звёздах, обязателен).
  Обрабатываются `pre_checkout_query` и `successful_payment`; ID платежа
  пишется в заказ и в лог — он нужен для возврата через `refundStarPayment`.

## Если хостинг блокирует api.telegram.org

Проверяется одной командой на сервере — ответа быть не должно только в случае блокировки:

```bash
curl -4 -sS -m 10 -o /dev/null -w '%{http_code}\n' https://api.telegram.org/
```

`000` означает, что провайдер режет трафик к Telegram: бот не сможет ни забирать
сообщения, ни отвечать. Лечится прокси — подойдёт любой HTTP или SOCKS5,
который сам до Telegram доходит:

```
TELEGRAM_PROXY=socks5://логин:пароль@1.2.3.4:1080
```

Прокси проверяется до запуска:

```bash
curl -4 -m 15 -x socks5://логин:пароль@1.2.3.4:1080 -o /dev/null -w '%{http_code}\n' https://api.telegram.org/
```

Любой код ответа, даже `404`, означает, что прокси рабочий — важно, что
соединение дошло. Если вместо этого соединение рвётся с `Connection reset by
peer`, попробуйте ту же строку со схемой `http://`: многие продавцы отдают
HTTP-прокси, а по SOCKS5 на том же порту сбрасывают соединение. После правки `.env` нужен `docker compose up -d --build`:
прокси требует библиотеку `aiohttp-socks`, она ставится при сборке образа.

Через прокси ходит только трафик к Telegram. Mini App отдаётся напрямую
через Caddy и от прокси не зависит.

## Работа продавца

В чате приходит карточка заказа с кнопками под текущий шаг. Команды:

| Команда | Что делает |
|---|---|
| `/orders` | открытые заказы (`/orders all` — все) |
| `/find NP-0001` | поиск по коду, UDID, юзернейму или ID |
| `/chat NP-0001` | переписка по заказу |
| `/reply NP-0001 текст` | ответить покупателю |
| `/log NP-0001` | история заказа |
| `/note NP-0001 текст` | заметка к заказу |
| `/stats` | счётчики по статусам |

То же самое во вкладке «Продавец» в Mini App — она видна только аккаунтам из
`SELLER_IDS`; остальным API отвечает 403.

## Переписка по заказу

Покупатель и продавец общаются в одной ленте, привязанной к заказу. Она
доступна из двух мест сразу, и это одни и те же сообщения:

- **В Mini App** — кнопка «Чат с продавцом» на экране заказа, у продавца
  «Переписка» в карточке. Новые сообщения подтягиваются каждые 5 секунд.
- **В чате бота** — покупателю достаточно написать боту обычным текстом.
  Продавцу приходит уведомление с кнопкой «Ответить»; можно и командой
  `/reply NP-0001 текст`.

Непрочитанные показываются счётчиком на вкладках и в списке заказов продавца;
отметка «прочитано» ставится при открытии переписки.

На шаге ввода UDID бот отличает номер от вопроса по виду сообщения: строка из
40 hex-символов уходит в проверку, всё остальное — продавцу в переписку.

Сообщения лежат в таблице `messages` и удаляются вместе с заказом, в том числе
по команде `/forget`.

## Команды покупателя

`/start` — витрина, `/order` — статус, `/udid` — где найти номер,
`/notify` — настройка уведомлений, `/about` — документы и реквизиты,
`/help` — помощь, `/forget` — удалить свои заказы и UDID из базы.

## Разделы Mini App

Нижний ряд: **Главная** (витрина и весь каталог с фильтрами), **Мой заказ**,
**О нас**, у продавца ещё **Продавец**. Каталог живёт на главной, отдельной
вкладки «Приложения» нет: нижний ряд держим коротким, чтобы хватало места
новым разделам.

В шапке две круглые кнопки: **помощь** и **переписка с продавцом**. Помощь —
обычный экран, а не вкладка, поэтому в Telegram на ней показывается системная
кнопка «Назад».

**О нас** — место для всего, что спрашивает платёжная система: описание услуги,
документы, контакты и реквизиты. Данные берутся из `.env` (`LEGAL_*`,
`CONTACT_*`, `*_URL`), те же сведения показывает команда `/about` в боте.

Под каждым экраном витрины — подвал с реквизитами продавца, контактами
и ссылками на документы.

## Витрина без Telegram

Адрес `WEBAPP_URL` открывается и в обычном браузере: тот же каталог с ценами
и описаниями, раздел «О нас» и документы, но без заказа и переписки — вместо
кнопки покупки там «Оформить в Telegram». Это то, что увидит модерация
платёжной системы: Mini App пускает только по подписи initData, и без
публичного режима проверить магазин невозможно.

Данные для этого режима отдаёт `/api/public` — без подписи и без чужих заказов.

С ширины 900px раскладка перестраивается под компьютер: витрина шире, разделы
переезжают из нижней панели в строку под шапкой и липнут под ней при прокрутке,
каталог идёт в четыре колонки, а ряды фильтров раскладываются в несколько строк.
Баннер и текстовые экраны выравниваются по центру страницы, каталог остаётся
во всю ширину. Настройка уведомлений в этом режиме скрыта — без подписи Telegram
сервер не знает, чей это аккаунт.

Строка разделов на ПК липнет под шапкой на высоте `--topbar-h`: её измеряет
`app.js`, потому что высота шапки зависит от подписи под названием.

Ряды фильтров прокручиваются колесом мыши и перетаскиванием: на компьютере
пальцем их не подвинуть, а в узком окне (например, в Telegram для ПК) они
не помещаются целиком.

## Документы

Тексты лежат в `webapp/legal/*.txt` и правятся без пересборки образа: папка
`webapp` примонтирована в контейнер.

| Файл | Адрес |
|---|---|
| `offer.txt` | `/docs/offer` |
| `refund.txt` | `/docs/refund` |
| `privacy.txt` | `/docs/privacy` |
| `consent.txt` | `/docs/consent` |

Разметка простая: `# ` — заголовок, `## ` — подзаголовок, `- ` — пункт списка,
пустая строка — новый абзац. Подстановки `{{legal_name}}`, `{{inn}}`,
`{{email}}`, `{{phone}}`, `{{support}}`, `{{price}}`, `{{site}}`, `{{updated}}`
заполняются из `.env`; если значение не задано, на его месте видно
`[укажите …]`. В текстах остались пометки в квадратных скобках — сроки и
удержания нужно заполнить перед подачей на модерацию.

Документ открывается внутри витрины, а по прямой ссылке — обычной страницей
с тем же подвалом. Согласие покупателя с офертой записывается в журнал заказа
событием `consent`.

## Приветствие

На каждый `/start` бот присылает картинку `app/assets/welcome.jpg` с подписью
(`texts.welcome`) и кнопками витрины. Когда покупатель просто открывает чат,
Telegram боту ничего не сообщает, поэтому приветствие приходит в ответ на `/start`:
первое нажатие «Начать», переход по ссылке на бота, команда из меню.

Картинка загружается в Telegram один раз, дальше бот шлёт её по `file_id`.
Если файла нет или Telegram его не принял, приветствие уходит текстом.

Заменить картинку — положить JPEG или PNG с тем же именем и пересобрать образ
(`docker compose up -d --build`): папка `app/` вшита в образ. Цена и число
приложений на картинке нарисованы — после смены `PRICE_RUB` или каталога
картинку нужно обновить, подпись обновится сама.

## Запуск без Docker

Пригодится, чтобы посмотреть проект на своей машине. `.env` читается
автоматически из корня проекта; переменные окружения, заданные снаружи, важнее файла.

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
python tools/preview.py            # http://127.0.0.1:8099 — UI без Telegram и токена
python -m app.main                 # живой бот: нужен .env с BOT_TOKEN и SELLER_IDS
python -m tests.smoke_test         # правила заказа + HTTP-API + подпись initData
python -m tests.bot_test           # хэндлеры бота на фейковых апдейтах
```

На Windows путь к интерпретатору — `.venv\Scripts\python.exe`.

`preview.py` поднимает только веб-часть в режиме `demo`, вход без подписи,
«сообщения в Telegram» печатаются в консоль. Токен не нужен.

`python -m app.main` работает откуда угодно, включая домашний компьютер:
бот забирает обновления сам (long polling), входящие порты и домен не нужны.
С пустым `WEBAPP_URL` весь путь заказа проходит в переписке.

## Бренд iApki

Ассеты лежат в `webapp/brand/`:

| Файл | Где используется |
|---|---|
| `logo.svg` | исходный логотип — знак и надпись на салатовом |
| `icon.svg` | знак «iA» без надписи: шапка Mini App, иконка вкладки, экран загрузки; салатовая подложка скруглена, чтобы во вкладке браузера не торчали углы |
| `avatar.svg`, `avatar.png` | аватар бота 640×640 с полями под круглую обрезку Telegram |
| `icon-512.png` | знак в растре — для каталогов ботов и соцсетей |

`webapp/brand.png` — растровый знак из дизайна, отдаётся как `apple-touch-icon`.

`icon.svg` и `avatar.svg` вырезаются из `logo.svg`, пути не перерисовываются —
после замены логотипа пересоберите их:

```bash
python tools/make_brand.py
```

**Аватар бота** Bot API поставить не умеет, это делается вручную: @BotFather →
`/setuserpic` → выберите бота → отправьте `webapp/brand/avatar.png` картинкой.

## Иконки приложений

В `webapp/icons/` лежат иконки всех 24 приложений каталога в PNG — из App Store,
Google Play и фирменных значков сайтов. Откуда взята каждая и её размер —
в `webapp/icons/sources.json`. Это товарные знаки их владельцев: право
показывать их в витрине — ваша зона ответственности.

Рядом лежат сгенерированные SVG-плитки (`tools/make_icons.py`) — запасной
вариант. Сервер выбирает PNG, если он есть, иначе SVG, иначе рисует букву.

Заменить иконку — положить файл с тем же слагом из `app/catalog.py`:

```
webapp/icons/sber.png
```

Пересборка образа не нужна: папка примонтирована в контейнер, сервер находит
файл при следующем открытии витрины.

## Инструкция по UDID

Покупатель получает UDID прямо на телефоне, компьютер не нужен: сайт
`udid.tech` → **Get My UDID** → установка профиля в Настройках → страница
показывает номер.

Картинка со скриншотами лежит в `webapp/img/udid-guide.webp` и показывается
в Mini App на экране ввода. Бот даёт на неё ссылку — она работает только когда
задан `WEBAPP_URL`, потому что картинку отдаёт тот же домен.

## Жизненный цикл заказа

Один открытый заказ на покупателя. Выполненный заказ новому не мешает:
на его экране есть кнопка «Оформить новый заказ», а сам заказ можно закрыть —
кнопкой «Закрыть заказ» у покупателя или 🗂 у продавца.

Заказ в работе (оплачен, но не выполнен) покупатель отменить не может —
это делает продавец, чтобы оплаченная работа не пропадала по случайному нажатию.

## Покупка отдельного приложения

Каждая карточка в витрине — кнопка: нажатие открывает оформление именно этого
приложения, кнопка «Весь каталог» — оформление всего каталога. Заказ запоминает
выбор, продавец видит его строкой «Товар» в карточке и уведомлениях.

Цена по умолчанию общая — `PRICE_RUB`. Своя цена приложения задаётся ключом
`price` в `app/catalog.py`:

```python
{"slug": "chatgpt", "name": "ChatGPT", "category": "Нейросети", "color": "#10A37F", "price": 990},
```

Если покупатель передумал до оплаты, его неоплаченный заказ просто переключается
на новый выбор. Заказ, по которому уже нажато «Я оплатил», не меняется — деньги
могли уйти за другой товар.

## Уведомления

Каждый решает сам, что присылать ему в чат бота. Настройки живут в Mini App
(«Помощь» → «Настроить уведомления») и в боте по команде `/notify`.

Покупателю доступны два переключателя — статус заказа и сообщения продавца.
Продавцу пять: новые заказы, оплаты, полученные UDID, сообщения покупателей,
запросы помощи.

Поверх общих настроек работает режим **для конкретного заказа**:

| Режим | Что делает |
|---|---|
| По общим настройкам | обычное поведение |
| Всегда уведомлять | шлём, даже если вид выключен целиком |
| Не беспокоить | молчим по этому заказу, остальные приходят как обычно |

Настройка заказа сильнее общей — так можно выключить, например, все оплаты и
оставить только один заказ, за которым следите. У продавца режим переключается
кнопкой 🔔 в карточке заказа, у покупателя — на экране настроек.

Выключенное уведомление не теряет данные: статус заказа и инструкция всегда
остаются в Mini App, просто не приходят сообщением.

## Что стоит знать

- **UDID — персональные данные.** Он хранится в открытом виде (продавцу нужен
  рабочий номер), покупателю показывается замаскированным, `/forget` удаляет
  заказы вместе с ним. Если сервисом будет пользоваться кто-то кроме вас,
  опишите это в условиях заказа.
- **Принимается UDID из 40 символов — это старый формат.** Устройства начиная
  с iPhone X сообщают UDID из 25 символов с дефисом (`00008030-001C2D3E1E88802E`).
  Такой номер форма отклоняет с отдельным пояснением. Чтобы принимать оба
  формата, разрешите ветку `_MODERN` в `app/udid.py` и поправьте длину в
  `webapp/app.js` — остальной поток от формата номера не зависит.
- **Базы, созданные до перехода на UDID, мигрируют сами** при первом запуске:
  колонки `imei`/`imei_at` переименовываются, старый статус заказа обновляется.
- **Один открытый заказ на пользователя.** Выполненный заказ не блокирует
  следующий — см. «Жизненный цикл заказа».
- Подпись `initData` проверяется на каждый запрос к API, срок жизни —
  `INIT_DATA_TTL`. Панель продавца дополнительно сверяется с `SELLER_IDS`.
